@ S553 ONE resolver, and a per-photo retirement test. Retiring the inline picture from a Diesel report is a REFACTOR, not a switch: about forty places read those bytes directly and SYNCHRONOUSLY (baking a markup layer, building the PDF, uploading, making a backup), while the device's own file is an ASYNCHRONOUS read. Flip retirement on before those places can wait and they get an empty string — a blank page in a client's report, a markup baked onto nothing. resolveSrc is the single door they must all come through; its order is deliberate (inline while it exists, then THIS DEVICE'S file, then cloud — the local file is preferred over cloud because it works with no signal, which is the case the store exists for). Object URLs are minted once per photo and cached, or a 200-photo gallery mints 200 more on every repaint; release() must be called when a report closes or they pin every image in memory. retirable() gates PER PHOTO and never per device: the file must be held here AND the upload confirmed, both, because either alone is a single point of failure. Note the cloud side has ALWAYS been retired this way (_keepD drops the picture once r2Status==='uploaded'), which is why no version floor and no fleet-wide check is needed for the local side — the inline copy never crosses devices. _localSrc is a live object URL and must NEVER be persisted; _stripPhotos rebuilds photo records field-by-field, which is what keeps it out.
