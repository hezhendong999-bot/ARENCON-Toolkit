05Step 1 Harness — live module tests

IDB: running… Auth: running… ScrollLock: running… Order rule: running…

IDB = round-trip (put/get/getAll/del) on Electric's OWN database via the parameterized factory. Auth = module load + session-restore smoke (the production 401→refresh path is code-identical to FRT's). ScrollLock = ref-count lock/unlock. Order = the enforcer demonstrably moves a mis-ordered Cancel to the correct slot.

06Step 2 Harness — R2 + Photo Outbox

R2 toolKey: running… Range-GET probe: running… Outbox resume: running… Ownership guard: running…

R2 toolKey = keys build as photos/{pid}/electric/… — Electric's own key space, never /frt/, same backend zero migration. Range-GET probe = the post-PUT existence check is a 1-byte Range GET, never HEAD (the S200/S421 worker rule). Outbox resume = a pending row written to Electric's OWN IndexedDB survives a fresh init() (upload survives reload). Ownership guard = the S398 rule — deleteDrawingAssets refuses to delete a PDF buffer still shared by a sibling drawing.

07Step 3 Harness — Merge + Sync Engine

Merge self-test: running… Photo resurrection: running… Canonical adapter: running… Off-thread merge: running…

Merge self-test = the built-in 3-way merge suite (14 tests) runs green against the extracted engine. Photo resurrection = the S43x deletion-wins guard — a purged photo stays deleted even when the shared history is lost, the exact bug that was fixed. Canonical adapter = ONE Electric state object satisfies both the sync engine (4 methods) and the Step-2 photo outbox (its 2 are a subset) — no duplication. Off-thread merge = the merge runs in a background worker so big projects don't freeze the screen; if a worker can't start it falls back to the main thread automatically, same result either way.
